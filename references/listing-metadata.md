# Book Description, Categories, and Keywords

Each format (paperback, Kindle eBook) has independent settings for these
three fields in the KDP dashboard -- fill in both if publishing both.

## Description
- KDP supports light HTML: `<b>`, `<i>`, `<br>`.
- First 1-2 sentences matter most -- Amazon truncates with a "read more"
  link, so the hook has to work standalone.
- 200-400 words is normal for nonfiction. Structure: hook -> what the book
  actually does -> a short bulleted list of concrete things inside -> a
  closing line that isn't just "buy now."
- Ground it in the book's actual content (a real scene, a real named tool)
  rather than generic superlatives -- specific beats grandiose.

## Categories
- Up to 3, chosen from KDP's browse-category tree (not raw BISAC codes for
  KDP-exclusive titles -- Amazon maps internally).
- Pick for genuine fit, not just to game a narrow bestseller list --
  reviews and returns from mismatched buyers hurt more than a slightly
  smaller category helps.
- One primary/obvious category, one adjacent category that matches a
  secondary theme in the book, one narrower category if a specific chapter
  or throughline supports it.

## Keywords
- 7 fields, 50 characters each, not shown publicly -- used for search
  indexing only.
- Do not repeat words already in the title/subtitle/author name/category --
  those are already indexed automatically; repeating them wastes a slot.
- Write them as real search phrases a reader would type, not just
  restating what the book is about in different words.
- Do not churn keywords right after launch chasing early rank -- resetting
  them repeatedly early on mostly just resets whatever ranking traction has
  started to build.
